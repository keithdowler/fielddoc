# Usability Standard

FieldDoc must be usable by field teams, office reviewers, owners, and customers across a wide age range. Screens should explain the next safe action without requiring product training.

## Principles

- Use "job" in user-facing mobile copy when referring to a local project.
- Show the next best action before secondary metrics.
- Make destructive actions confirm intent in plain language.
- Keep cloud, subscription, and provider configuration locked until the app can prove they are ready.
- Avoid hiding important state in icons alone.
- Prefer short sentences and concrete nouns.
- Preserve offline-first behavior: local capture and report preparation must stay usable without sign-in.

## Mobile Behavior

- Home shows first-run guidance, a primary next action, and recent local jobs.
- Projects supports local create, edit, search, sort, archive, and delete with confirmation before destructive actions.
- Capture explains whether the user should add Before, Work, or After evidence next.
- Reports surfaces the first blocked or incomplete checklist item before the full checklist.
- Settings explains account, subscription, backup, branding, privacy, and diagnostics in user terms before technical details.

## Web Behavior

- The workspace dashboard presents a recommended next action before the attention queue.
- Readiness settings explain what green and warning states mean.
- Provider readiness must stay explicit rather than pretending unavailable services are live.

## Copy Rules

- Say "Back Up Now" instead of "sync" when describing the user action.
- Say "original files" instead of "media assets" when speaking to nontechnical users.
- Say "report PDF" or "Proof Packet" instead of "export artifact."
- Use "needs attention" for recoverable work and "blocked" only when the user cannot proceed.

## Accessibility Rules

- Maintain large touch targets for primary mobile actions.
- Keep warning and error messages visible on screen.
- Use text labels with status icons.
- Preserve dynamic text support in forms, banners, buttons, and checklist rows.
- Confirm delete/archive actions in the main view, not only through transient alerts.
